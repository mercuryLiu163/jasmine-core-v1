## 1. 背景与动机

v1 判据要求 lesson 会话在七个探索类别中至少省略一个。三次有效实验（`32727e2`×2 旧文本、
`28ae83c`×1 完整有标签治疗）都显示双方类别完全相同。把“少一类”当中介信号过于粗糙——负责任的
Agent 会保留必要验证，但可能在每一类内部减少重复调查。v2 直接测量可观察成本：

- 主要指标：**达到正确诊断前的探索工具调用次数**（来自权威原生调用流与 Evidence，不采信自述）。
- 辅助指标：重复读取、无效尝试、探索轮次；耗时仅记录。
- 质量门槛不变：双方完成同一任务、修复正确、必要验证完整、不把历史原因断言为当前原因。

不声称一次示范建立统计收益；不冒充 §9 综合长任务或 P7 全量发布。

## 3. 权威调用流、动作粒度与 Evidence 绑定（冻结）

**权威序列**：该会话的原生 Codex JSONL（`codex exec --json` 输出）及其装配的会话 transcript。
**文件变更动作（`apply_patch` 等）是一等动作**——首轮 review 证实 28ae83c 的两个会话都用
`tools.apply_patch` 修复而当前装配器只提取 `command_execution`，因此本规格要求实现侧扩展：

1. 装配器把文件变更事件与 shell 事件一并提取；每个动作记录：动作类型、命令/patch 摘要、
   作用文件、读取或变更前后的内容哈希。
2. **每个进入指标计算的动作必须绑定 Core Evidence**（shell 用现有 `record_tool_result`，
   文件变更记录 patch 载荷与文件前后哈希）。任何动作无法绑定 → 该 run 判 **BLOCKED（指标不可
   计算）**，不放宽阈值、不事后补绑。
3. **粒度**：一次调用 = 原生流中的一个工具调用事件。批处理（`Promise.allSettled`）按原生流
   拆分的每个事件各计一次；复合 shell（`a; b`）仍计一次。非 shell 的读取（MCP/工具读文件）
   同样计入 E。
4. 分类（由动作类型与捕获字节推导，不采信会话声明）：
   - **E 探索**：只读信息收集——列目录、读文件、`git log/diff/show`、版本查询、**首个 R 前的**
     套件运行（复现）、算术探测、构建产物检查、非 shell 读取。
   - **R 修复**：**由文件前后哈希判定的**文件变更动作（`apply_patch`、写文件、`git apply`、
     指向修复的 `checkout`），与命令文本无关。
   - **V 验证**：**首个 R 之后**的套件运行。
   - **O 其他**：其余；不计入 M。
   - 歧义：同一动作同时像 E 与 R 时计 E（对双方一致）；无法分类 → BLOCKED。
5. `baseline` 与 `lesson` 各自在**独立 worktree 副本**中运行（现共享工作树、reset 会覆盖
   baseline 的 diff）；每个会话结束后立即捕获其最终工作树快照，供 §5 判定。

## 4. 诊断成立与主要指标

**诊断观察集合 O\***，每项绑定“该动作捕获字节”的精确锚点（不是命令文本里出现过）：
1. 一次套件运行动作，其捕获 stdout 含 `AssertionError: 25.0 != 27.5`；
2. 一次读取动作，其捕获内容为该文件当时的 `calc.py`，字节中含精确行 `return sum(prices) - discount`；
3. 一次读取动作，其捕获内容为 `NOTES.md`，字节中含精确行 `The discount is in percent, not currency.`

一次动作可同时满足多项（例如一次批处理读取同时给出 2 与 3）。

**诊断时刻** = 动作序列中使 O\* 首次齐备的那次动作序号。
**兜底（保守）**：O\* 始终未齐备时，诊断时刻 = **序列末尾**，M = 整个会话的全部 E 调用数；
不采用“首个 R”兜底（首轮 review：那会奖励“不诊断直接改”）。

**主要指标 M** = 诊断时刻之前的 E 类调用次数。

**辅助指标**（同一时间窗前）：
- 重复读取：同一规范化路径在首次读取之后、诊断时刻之前的读取次数；
- 无效尝试：其文件变更最终未进入该会话正确 diff 的 R 动作数（由文件哈希判定，patch 可见后不再
  空转）；
- 探索轮次：诊断时刻之前 E 类动作的极大连续段数；
- 耗时：会话开始到诊断时刻，仅记录。

## 5. 质量门槛（明确为新增/扩展工作，不臆断复用）

1. 两个会话都完成同一任务（现有`_session_completion`）。
2. **各会话最终工作树 diff 等于正确修复**：`calc.py` 为 `return sum(prices) * (1 - discount / 100)`、
   `test_calc.py` 期望为 `28.5`——**新增检查**，基于 §3.5 的每会话独立快照；baseline 的 diff 在
   任何 reset 之前捕获。
3. **首个 R 之后**至少一次绿色套件运行并绑定真实 Evidence——在现有 green-run 检查上**扩展**位置
   要求；缺失判质量 FAIL（“靠不验证省步骤”不可行）。
4. **精确引用**：lesson 会话答案须同时含 memory id、失败 Evidence id、来源 task id 三者
   （现有检查仅“memory 或首个 evidence”，**扩展为三元组**）；baseline 不得声称见过 Memory；
   历史原因不得被断言为当前原因（现有词窗检查 + **为 G01 新增独立语义复核**，复用
   `semantic_review` 机制）。
5. 原生 SessionStart 回执绑定（现有）。

## 6. 判定（预注册，运行后不得修改）

- **PASS** 需同时满足：
  - 主要：`M(lesson) ≤ M(baseline) − 2` **且** `M(lesson) ≤ 0.75 × M(baseline)`；
  - 辅助不回退：`重复读取(lesson) ≤ 重复读取(baseline)`、`无效尝试(lesson) ≤ 无效尝试(baseline)`、
    `探索轮次(lesson) ≤ 探索轮次(baseline)`；
  - 质量门槛双方通过。
- `M(baseline) < 4` 判 **FAIL（不可测）**：baseline 已达最小探索，改善不可测（预注册条件，
  不是放宽标准）。规格如实承认：若 baseline 的 E 数天然很小，本实验可能没有可达到的 PASS 区，
  此时如实报 FAIL。
- 任一质量门槛不过 → FAIL（即使 M 更低）。
- 其余 → FAIL，并给出完整指标表。

阈值理由：在无任何 v2 结果时选定；v1 观测的 baseline 探索动作约 5–7 次，2 次且 25% 是可测量的
最小有意义改善。实现阶段若发现分类/绑定无法客观计算，回 reviewer 修订规格后重跑，而不是运行后
调阈值。

## 7. 实验数量与重跑纪律

- 恰好 **1 对**（1 baseline + 1 lesson），使用 §2 冻结输入。
- 两个会话都完成后指标即为最终；**不得**因结果不利重跑。
- 会话开始前的环境性阻断（引擎不可达、hook/信任失效，尚未产生样本）判 BLOCKED：修复并记录阻断
  事实后可重试，但不得在观测到任一侧 M 之后重试。
- 会话崩溃/未完成（无样本）判 FAIL，不替换。
- BLOCKED 的指标不可计算同样不替换；修复机制后按新规格 SHA 重新冻结、重新运行。

- M 由权威调用流 + Evidence 推导；文件变更必须可见且绑定；无法绑定即 BLOCKED。
