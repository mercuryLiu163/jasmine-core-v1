# P4-G01 v2 规格：以“诊断前探索成本”为收益判据

状态：**冻结草案，待独立 reviewer 确认；尚未实现、尚未运行**。本文件是 G01 的版本化规格，
自批准之日起取代 v1 的“探索类别必须少一类”判据；v1 的全部阴性结果保留为 FAIL 记录，不因 v2
作废。任务域不变（同一夹具、同一 prompt、同一 baseline/lesson 两个 pack）。

## 1. 背景与动机

v1 判据要求 lesson 会话在七个探索类别中至少省略一个（`omitted = baseline - lesson ≠ ∅`）。三次
有效实验（`32727e2`×2 旧文本、`28ae83c`×1 完整有标签治疗）都显示：双方类别完全相同，会话在
获得明确诊断后仍执行必要的复现、算术核验与验证。把“少一类”当中介信号过于粗糙——**负责任的
Agent 会保留必要验证，但可能在每一类内部减少重复调查**。v2 因此直接测量可观察的成本：

- 主要指标：**达到正确诊断前的探索工具调用次数**（来自原生 transcript 与 Evidence，不采信自述）。
- 辅助指标：重复读取、无效尝试、探索轮次；耗时仅记录，不作为判据。
- 质量门槛不变：双方完成同一任务、修复正确、必要验证完整、不把历史原因断言为当前原因。

不声称一次示范建立统计收益；本阶段不冒充 §9 综合长任务或 P7 全量发布。

## 3. 动作分类（冻结）

工具调用流取自原生 transcript（Codex JSONL）与 Core Evidence；只有绑定真实 Evidence 的调用
计数。按命令文本与相对首个修复动作的位置分类：

| 类 | 判定（命中任一即归类） | 示例 |
| --- | --- | --- |
| E 探索 | 只读信息收集 | `ls/find`、读文件（`cat/head/tail/sed -n`、只读 `grep`）、`git log/diff/show`、解释器/runner 版本查询、**首个修复前的**测试运行（复现）、算术探测（`bc`、`python -c` 含运算符、heredoc 求值）、构建产物检查（`__pycache__`、`.pyc`、`git stash/fsck`） |
| R 修复 | 写入被跟踪文件 | 重定向写入、编辑命令、`patch`、`git apply`、改变工作树指向修复的 `git checkout --`、写文件的 heredoc |
| V 验证 | **首个修复后**的测试套件运行 | `unittest`/`pytest` |
| O 其他 | 不属于以上 | 引用整理等；不计入 M |

规则：同一命令同时命中 E 与 R 时计为 **E**（保守，且对双方一致）；类别由 transcript 推导，
不采信会话声明。

## 4. 诊断成立与主要指标

**诊断观察集合 O\***（该夹具正确诊断的最小充分观察，冻结）：
1. 复现失败断言（首个修复前的一次套件运行，输出含 `AssertionError`）；
2. 读到 `calc.py` 修复前行（含 `sum(prices) - discount`）；
3. 读到 `NOTES.md` 百分比规则行（含 `percent`）。

**诊断时刻** = 工具调用序列中使 O\* 首次齐备的那一次调用的序号。
兜底（保守，且写入 manifest 以便审计）：O\* 始终未齐备时，诊断时刻 = 首个 R 调用；无 R 调用时 =
序列末尾（其前全部 E 计数）。

**主要指标 M** = `诊断时刻` 之前的 E 类调用次数。M 低表示以更少探索达到同一诊断。

**辅助指标**（同一时间窗前计算）：
- 重复读取：同一规范化路径在首次读取之后、诊断时刻之前的读取次数；
- 无效尝试：其改动未进入最终正确 diff 的 R 调用次数（最终 diff 由工作树与夹具正确修复逐字节比对）；
- 探索轮次：诊断时刻之前 E 类调用的极大连续段数；
- 耗时：会话开始到诊断时刻，仅记录。

指标计算只读原生 transcript 与已核验 Evidence；任一调用无法绑定 Evidence 时该 run 判
**BLOCKED（指标不可计算）**，不得放宽阈值。

## 5. 质量门槛（不变）与判定

质量门槛（双方都必须满足，独立于 M）：
1. 两个会话都完成同一任务；
2. 最终工作树 diff 等于正确修复（`calc.py` 百分比公式、测试期望 28.5）；
3. 至少一次最终绿色套件运行绑定真实 Evidence（“靠不验证省步骤”直接判质量不过）；
4. lesson 会话按 prompt 精确引用 memory id / evidence id / 早前 task id，且不把历史原因断言为
   当前原因；baseline 不声称见过 Memory；
5. 原生 SessionStart 回执绑定（已有机制）。

判定（全部预注册，运行后不得修改）：

- **PASS** 需同时满足：
  - 主要：`M(lesson) ≤ M(baseline) − 2` **且** `M(lesson) ≤ 0.75 × M(baseline)`；
  - 辅助不回退：`重复读取(lesson) ≤ 重复读取(baseline)`、`无效尝试(lesson) ≤ 无效尝试(baseline)`、
    `探索轮次(lesson) ≤ 探索轮次(baseline)`；
  - 质量门槛双方通过。
- `M(baseline) < 4` 时判 FAIL，理由“baseline 已达最小探索，改善不可测”（预注册的不可测条件，
  不是放宽标准）。
- 任一质量门槛不过 → FAIL（即使 M 更低）。
- 其余 → FAIL，并给出完整指标表。

阈值理由（在无 v2 结果时选定）：v1 观测的 baseline 探索动作约 5–7 次；2 次且 25% 是可测量的
最小有意义改善，不是从 v2 结果反推。若实现阶段发现分类规则无法在机制上客观计算，应回到
reviewer 修订规格后重跑，而不是运行后调阈值。
