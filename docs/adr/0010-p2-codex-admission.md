# ADR 0010 — Real Codex capture and synchronous semantic admission

Status: Accepted contract; implementation and independent validation in progress. Actual project/hook trust and real capture Gate have not been verified. Schema remains 8. User override removes CI and per-stage push requirements; one publication occurs after P2 completion.

## 1. Bound scope and independent barrier

The P2 primary main Codex is **admission-only, execution-free**, fixed gpt-6.1-sol and validated CLI/catalog. Hooks are enabled on main; the data-only Interpreter remains separate with hooks disabled. P2 demonstrates real natural input → immutable Raw → Interpretation → Policy/Resolution → Task/requirement/current-state injection and actual operator maintenance. It does not demonstrate Playwright execution. P3 must add a reviewed typed Guard and independent execution barrier.

Codex hook timeout/error/malformed output may fail open. A successful bound PreToolUse returns deny for every tool in this P2 mode, but hooks alone are not an absolute execution guarantee. The actual main request must expose no executable tools, including nested additional_tools, hosted tools, code/shell/apply_patch/browser/MCP/write_stdin/sleep. Only inactive Plan request_user_input may be declared; exact-profile forced calls must be rejected in Default without UI/actions. Component simulation establishes capability boundaries; it is distinct from real saved-auth LLM/capture evidence.

## 2. Credential and filesystem boundary

File modes 0600/0700 are hygiene, not same-UID isolation. Main uses a named permission profile without legacy sandbox flags: approval never, local command network disabled, fixture root read-only, only fixture/work writable, protected deployment source/scripts read-only, private runtime deny read/write. Code/runtime/fixture roots must be disjoint. Fixture root read-only protects wrapper/config ancestor rename/replacement. The code deployment contains only current package and necessary scripts, not repository artifacts or prior-stage credentials. Catalog, DB/WAL/SHM, binding/nonce/lease, token files and operator plans stay in runtime. Every deployment source/config/catalog/binary fingerprint is checked before launch.

Main profile freezes all feature/config values and digest. Normal user config/trust loads; invocation overrides disable every inherited MCP server with a whole valid disabled table and notify=[], while rejecting non-fixture user hook definitions. Inherited legacy sandbox_mode must be proved overridden by the effective named profile before real Gate; an unproved decorative metadata flag does not authorize launch. Default mode, model gpt-6.1-sol, HTTP/SSE official saved auth, no custom base URL/API keys, no plugin/app/agent/code/shell/browser/file execution features. Main hooks=true is separate from Interpreter hooks=false. Tool environments exclude Jasmine capabilities; parent trusted hook must separately prove access outside tool sandbox. Effective permission state, runtime native/direct/alias reads and writes, wrapper/config ancestor modification negatives, full actual request and forced-function negatives are required final Gate proof. Unsupported runtime remains BLOCKED, never substituted with chmod or trust bypass.

Capture credential: human events:write only. Processor: system read/process plus state:write bookkeeping, no approvals. Core-side automatic executor remains trusted system/home-host bound. Host operator credential is separate and never in binding/argv/hooks/main prompt. Authorized isolated fixture operations use genuine trusted **system** command Events, not fictional human clicks; production human CLI actions remain explicit.

## 3. Total budget, Raw-first and private state

At hook entry use monotonic deadline140 seconds (UserPromptSubmit definition150); provider deadline120, interpret call cap125, other API call cap3, lease lock cap1. Every call timeout uses remaining budget. HTTP runs in an owned child process: parent deadline bounds slow headers and repeated reads independently of socket timeout resets. Responses cap2MiB. Expiry terminates/reaps only that owned HTTP child and preserves exact persisted request for ambiguous server commit. Pre/Post hook budget8, definition12.

Before **any** network call, a genuine new turn invalidates prior READY durably as PENDING_CAPTURE. State binds exact session/turn/prompt SHA/event ID/generation. File replacement uses fsync/rename plus directory fsync. Locks open nonblocking, no-follow, checked regular/private/owner to reject FIFO/symlink. Diagnostics are bounded best-effort nonblocking and never replace a block decision. OS filesystem calls may themselves stall; no real-time guarantee is claimed for kernel fsync. Check budget after writes and before returning context; READY includes its monotonic deadline, so an overdue marker cannot authorize success.

Phases: PENDING_CAPTURE → CAPTURED → EXTRACTED/FAILED/INTERRUPTED/PROCESSING → APPLIED/SOURCE_REPLAYED/NO_ACTION/PENDING_REVIEW → STEP_BINDING_PENDING → READY. RERUN_PENDING/REJECTED and CAPTURED_UNBOUND_BLOCKED are explicit blocked/terminal outcomes. Unknown or unavailable state blocks; no empty context implies an instruction was applied.

Persist exact method/path/body before every mutation. Retry same key never refreshes expected revisions or original body. A new turn's Raw is committed before recovering prior operation. Archive one active prior operation separately rather than nesting entire histories in the lease. Reject releases old pending without retracting Truth. Correct/Rerun follows authoritative maintenance head, preserving old requests and exact source; completed Rerun is read/recovered without starting another LLM run. A new child can have its own exact Resolve request, subject to normal source canonical dedup; no automatic manual-reapply.

If prior task-null recovery creates a Task only after current Raw committed task-null, current turn remains CAPTURED_UNBOUND_BLOCKED. Preserve that immutable Raw and do not interpret/resolve it with an invented Task link. Next genuine turn captures the recovered trusted Task/Step. Never rewrite source or rebind old model output.

## 4. Derived Task and bookkeeping Step

Start fixture with known Project and zero Tasks/Steps. Resolve permits Task creation atomically with requirement. Validate canonical action binding_event_id through immutable interpretation.bound Event, exact source/project/task/host and actual execution/review actor, canonical Resolution and Interpretation. Automatic binding uses trusted system executor; authorized manual binding may use human/system operator and must match immutable successful approval provenance. Neither review results nor source-replayed result are assumed to carry new source_binding rows.

Create one bookkeeping PLANNED Step through existing P1 API using saved exact event ID/expected Task revision/body. Empty criteria is operational binding, not evidence, approval or verified work. Response-loss exact replay returns original Step. Raw.task_id=null remains null. Subsequent captures use trusted derived Task/Step. No automatic status transition, ACCEPTED/VERIFIED or Evidence PASS is produced.

## 5. Sole coherent state injection

One shared serializer, one additionalContext path. Fetch full Resolver preview revision membership+digest/head; independently read every Project/Task/Step/applicable Rule and match ID and revision. Fetch preview again; exact membership/digest/head equality required. At most one retry within remaining budget. Only ACTIVE Rule content is injected; inactive Rules contribute revision membership and history refs, never effective Authority prose. Current Task must be ACTIVE and Step must belong to it. Max8KiB, no truncation of HARD rules. Provenance/source/int/res/review/binding refs included, credentials excluded. P3 extends this sole path into actual Context Builder; P2 snapshot is not a P3 Context Pack.

## 6. Artifacts, trust and acceptance

Installer defaults review-only, prints exact definition diff/hash and wrapper hash; explicit --write affects only fixture project-local definitions, preserving unrelated/P0 entries and backing up previous bytes. It never edits global config/trust or services. UserPromptSubmit150, Pre/Post12, latter match all tools. P1 legacy handler/installers remain unchanged.

Prepare creates a fresh isolated fixture/private runtime/protected deployment, Schema8 DB with zero Tasks/Steps, purpose keys and exact hook definition; reports PREPARED_NOT_VERIFIED. Operator CLI requires explicit action and exact private request body/revisions/reason/key. Real runner submits genuine Codex exec/resume stdin; synthetic handle(payload) is never a real acceptance path. --user-reviewed-trust is only a prerequisite, not proof. Actual hook trace/current Raw hashes/DB graph must agree. Main deliberately retains normal user config and trust loading; --ignore-user-config is absent. Whole-table disabled MCP and notify=[] overrides prevent inherited service startup. Independent normal-loader probes established the effective named permission profile despite the existing legacy sandbox_mode. These exact-profile proofs remain required for each frozen candidate/fixture. Prepare emits a normal interactive trust command with the same security overrides and no admission nonce. No trust hash is invented/copied/generated by runner.

Required proof: exact-profile component fullsurface/forced/defaultmeta and effective sandbox negatives; normal-interface exact project/hook trust; actual hook outside sandbox positive; real fresh Task-null natural objective and Playwright requirement; real same-session new correction Raw+pending+authorized system fixture review+dual provenance; tentative no confirmed Decision; operator Correct/Reject/Rerun actual commands; pending/error block with Raw surviving; exact replay no duplicate Task/Step; owned Core restart graph. Each failed receipt retained. Components/local suite are not real Gate PASS. P3 execution/context/checkpoint/compact remain separate.
